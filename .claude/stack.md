## Next.js 16.4.6: images
- **Use:** `getImageProps()` from `next/image` and render a plain `<img {...props} alt="" />` in the Server Component. No client `Image`. `@next/next/no-img-element` is off only for `apps/*/src/modules/site-shell/**/*.tsx`, so these images live in site-shell.
- **Patterns:** above the fold use `loading="eager"` or `fetchPriority="high"`. With art direction (several `<source>`/`<picture>`), `fetchPriority="high"` on the `<img>`; `preload` and `loading="eager"` would load both images.
- **Avoid:** `priority` (deprecated in 16 in favour of `preload`). The docs advise `loading="eager"` / `fetchPriority="high"` over `preload` in most cases, and never `preload` alongside `loading` or `fetchPriority`.
- **Hosting:** Netlify serves `next/image` through its Image CDN via the OpenNext adapter with no config. VERIFIED 2026-11-24: the adapter's `setImageConfig` (opennextjs-netlify `src/build/image-cdn.ts`) rewrites `/_next/image` to `/.netlify/images?url=:url&w=:width&q=:quality` and never reads `images.formats`; with no `fm`, Image CDN serves WebP when the `Accept` header allows it, else AVIF, else the original (docs.netlify.com/build/image-cdn/overview, Format). ## Mantine 9.8.2 in React Server Components
- **Fact:** every `@mantine/core` component file starts with `"use client"` (checked in `esm/components/Button/Button.mjs`, `Title/Title.mjs`). A Server Component page may render them, but only with serialisable props: no `renderRoot`, no function props, no callback children.
- **Compound parts:** `Popover.Target` etc. fail in server files; use the flat export (`PopoverTarget`) or put the file behind `'use client'`.
- **Polymorphic:** `component="a" href="..."` retypes the props to the element's. A string `component` is safe from a server page; a component reference is not (see the next-intl fact).
- **Container sizes are not global:** `--container-size-{xs..xl}` are declared only on the Container root class (`.m_7485cace` in `styles.css`), so `var(--container-size-xs)` outside a `Container` is invalid at computed time (Stylelint still passes it). `--mantine-breakpoint-*` and `--mantine-z-index-*` are on `:root`. Rendering `Container` adds its client JS (see the chunk split entry).
- **Title:** `order` picks the element (h1-h6, default 1) and its theme size; `size` changes only font size (and line height only between h1-h6 sizes). Choose `order` for semantics, `size` for visual override. Trama keys letter-spacing off `order`, through the theme's `styles`, which Mantine renders as an inline `style`: a `.t-*` class sets the size but cannot override that letter-spacing (measured: `Title order={1} className="t-display-md"` computes -0.704px, display-lg's).
- **Chunk split (since @nasqa/trama-react 0.1.2, nasqa/trama#21):** Trama's theme configures Mantine with plain objects and imports no component, so a page ships only the Mantine components it renders, each on the routes that render it. Up to 0.1.1 the theme imported 31 components to call `.extend` and every route shipped all of them with floating-ui (74.8 to 94.2 kB gzip per route, measured 2026-11-25). `Component.extend` returns its argument unchanged (Mantine 9.8.2), so a client module that imports a component only to extend it ships that component again. Measure with a probe before adding any Mantine component to a page; for headings use a plain `<h1 className="t-display-md">` (AGENTS.md's `.t-*` classes).
- **Islands (MEASURED 2026-11-24 on trama-react 0.1.1, when every route already shipped Accordion; gzip -9 of every `<script src>`, `next start`):** `Accordion` in a `'use client'` island: /es −104 B and −352 B on every other route (Trama already ships it; the chunks re-split). `CopyButton` island: +470 B on /es only.
- **Accordion SSR:** a closed panel is a `Collapse`. With the default `keepMountedMode="activity"` its content sits in a hidden React `Activity` and is left out of the server HTML; with `"display-none"` it is in the HTML but `display:none`, `opacity:0`, `aria-hidden="true"` and `inert`. Without JavaScript, show a plain list in `<noscript>` and hide the accordion there (the home's FAQ does).
- **Breakpoints are em:** `var(--mantine-breakpoint-lg)` is `75em`, resolved against the font size of the element that uses it: inside a `.t-body-sm` box it is 1050 px, not 1200. Use it on boxes without a text style.
- **Sources:** Context7 `/mantinedev/mantine/9.0.0` (guides/next, help q/server-components, core/title, guides/polymorphic), 2026-11-23; installed `@mantine/core/esm` (`Collapse/Collapse.mjs`, `@mantine/hooks/esm/use-collapse`).

## next-intl 4.15.3
- **Routing here:** locales es/en, `localePrefix: 'always'`, `localeDetection: true`, `alternateLinks: false`, localised `pathnames`. Navigation APIs come from `createNavigation(routing)` in `@/i18n/navigation`.
- **Link:** `<Link href={{ pathname: '/x', query: { a: 'b' } }} locale="en">` works in Server Components; `locale` switches language and sets `hreflang` on the anchor, but only when it differs from the current locale (`LocaleChangingLink` in `navigation/shared/BaseLink.js`); pass `hrefLang` yourself on the current-locale link. The href always carries the locale prefix when `locale` is given. (Types: `BaseLink.d.ts` has `locale?: Locale`.)
- **Cookie:** the `NEXT_LOCALE` cookie is synced when a locale-prefixed path is visited (the docs' reason a `locale` Link keeps the prefix). `localeDetection: true` negotiates the locale from the cookie and `accept-language` on unprefixed paths: an en-US browser at `/` or `/privacidad` gets a 307 to `/en` or `/en/privacy` (verified 2026-11-24 on a `next start` build). `localeCookie: false` disables the cookie.
- **getPathname:** `getPathname({ locale, href })` returns the localised, prefixed path string; `href` may be `{ pathname, query, params }`. Never prepend the locale by hand.
- **hasLocale:** `hasLocale(routing.locales, value)` from `next-intl` narrows to a `Locale`; use it in request config and `notFound()` when false.
- **Composing (proxy.ts):** `createMiddleware(routing)` returns `(request) => NextResponse`; call it, then inspect or replace the response (Context7 `/amannn/next-intl` routing/middleware, "Composing other middlewares", "Additional rewrites"). Here, for the exact path `/` only, a 307 whose `Location` pathname is `/es` becomes `NextResponse.rewrite('/es' + search)` with only the cookies copied over (the redirect's headers carry `Location`); every other response is returned as is. The `[locale]` root param of the rewritten path gives the locale, so no `X-NEXT-INTL-LOCALE` header is needed. `syncCookie` may set `NEXT_LOCALE` on an unprefixed request with no `Accept-Language` (measured: `set-cookie: NEXT_LOCALE=es` on `/`).
- **Cookie wins:** on an unprefixed path the locale is the prefix, else the `NEXT_LOCALE` cookie, else `Accept-Language`, else the default (`middleware/resolveLocale.js`): `NEXT_LOCALE=en` with `Accept-Language: es-CO` still gets the 307 to `/en`.
- **hreflang:** next-intl's own Link header uses the unprefixed path as x-default; this app uses the default locale's page instead (`/es`, `/es/privacidad`), because `/` serves the Spanish home with `/es` as its canonical.
- **Netlify:** the OpenNext adapter runs Next middleware as an Edge Function in front of the CDN cache (docs.netlify.com/integrations/frameworks/next-js/overview, "Middleware: Full support"), so the 200/307 choice at `/` is made per request. Its limitation on rewrites applies to `next.config` `beforeFiles` rewrites that target `public/` files, not to middleware rewrites to a page.
- **Sources:** Context7 `/amannn/next-intl` (routing/navigation, routing/configuration, setup), 2026-11-23; installed `next-intl/dist/types`.

## Playwright specs (VERIFIED in this repo 2026-11-25)
- With `javaScriptEnabled: false`, Chromium parses `<noscript>` content into real elements (probe: 1 anchor with JS off, 0 with it on), so a DOM walk there reads the fallbacks.
- A hook or test refuses a default value in its fixture destructuring (`({ baseURL = '' })` fails to load with "unknown parameter"); resolve it in the body.
- A fixture's second parameter named `use` trips `react-hooks/rules-of-hooks` (React 19's `use`); name it `provide`.
- Playwright 1.65.1 never sees a `keepalive` fetch sent while a document unloads (pagehide, visibilitychange on a full navigation): no route, no `request` event, not even a page CDP session's `Network` events. It goes straight to the network, so `route.abort()` cannot stop it; only `--host-resolver-rules` can. Chromium's NetLog (`--log-net-log=<file> --net-log-capture-mode=Everything`, read after `browser.close()`) records it: `URL_REQUEST_START_JOB` for every address, `SOCKET_BYTES_SENT` (base64) for the bytes on the wire.
- `--host-resolver-rules=MAP host 127.0.0.1:3100,MAP * ~NOTFOUND,EXCLUDE localhost` works in the headless shell, and `response.serverAddr()` reports the mapped address even when a context route `continue()`s the request. A `.app` name cannot be mapped to plain HTTP: the TLD is HSTS-preloaded, so Chromium upgrades it and fails with `net::ERR_SSL_PROTOCOL_ERROR`.
- React 19's hydration mismatch in a production build reaches Playwright's `pageerror` as "Minified React error #418".

## Netlify build vs runtime environment (VERIFIED 2026-11-24)
- **Fact:** `CONTEXT`, `DEPLOY_URL` and `DEPLOY_PRIME_URL` exist only while building. Netlify Functions (every server action and dynamic route of the OpenNext adapter) see only `URL`, `SITE_NAME` and `SITE_ID` at runtime (docs.netlify.com/build/functions/environment-variables, "Netlify read-only variables"). A value that depends on the deploy context must be chosen at build and inlined.
- **Pattern here:** `next.config.ts` picks the site address (`DEPLOY_PRIME_URL` for `deploy-preview`/`branch-deploy`, else `URL`) and sets `env: { SITE_URL }`; Next's `env` config is a define replacement in every bundle, server included (`next/dist/lib/static-env.js` `getNextConfigEnv` skips null/undefined values, so a local build leaves `process.env.SITE_URL` to the runtime). Checked on a build with a fake preview env: server chunks hold `new URL("https://deploy-preview-99--…")`. Only `process.env.SITE_URL` member reads are replaced, never destructuring.

## Analytics: Plausible, Netlify order, locale cookie (read 2026-11-25; nothing is installed yet)
- **Snippet:** each site has its own script (`pa-XXXXX.js`) plus an inline `plausible.init({ ... })`. Options include `endpoint` (proxy), `transformRequest` (change or drop an event), `autoCapturePageviews`, `captureOnLocalhost`. The click handler looks for the tag at most 3 parents up. The source has a compat branch that calls `preventDefault()` and then `form.submit()` on a tagged form, which would bypass a React server action. VERIFIED by static reading of a live per-site script (plausible.io's own, `v` 37, 2026-11-25): no `preventDefault`, no `.submit()`, no storage or cookie write (it only reads `localStorage.plausible_ignore`); 2,491 B gzip, 2,493 B br. - **Plans:** custom properties, funnels and the Stats API are Business only.
- **Dashboard (docs/add-website, docs/custom-event-goals):** the site's *Domain* is entered without `www`; the hostname allow-list takes the real host. Goals also count events received before the goal existed, and the dashboard can add every event already received in one step.

- **A meta referrer policy is too late (MEASURED 2026-11-25, next 16.4.6):** React 19 writes `<script async>` above the metadata, so on `/es/confirmar?t=…` the scripts, fonts and styles went out with the full address in `Referer` despite `referrer: 'no-referrer'`. Headers that depend on a localised path go in the proxy, and are checked with `curl` on a deploy preview.
- **Netlify proxy headers:** a 200 rewrite passes the browser's headers to the destination (cookies confirmed by Netlify staff, answers.netlify.com/t/112442). The `headers` map of a rewrite adds request headers; whether it overrides an incoming `Cookie` or `Referer` is unverified.
- **Netlify order:** framework edge functions (the Next proxy) run before `netlify.toml` redirects and rewrites, so a proxied event path must be excluded from the proxy matcher or next-intl redirects it. `netlify.toml` does not interpolate environment variables (a `sed` in the build command can).
- **Next 16 matcher:** its values must be constants; imported or computed values are ignored. Guard the agreement with the rewrites in a test.
- **Locale cookie (measured on a local `next start`):** `NEXT_LOCALE` (session, `SameSite=lax`) is set when the page's locale differs from what `Accept-Language` asks for, or the header is missing; `syncLocaleCookie` also writes it on a client-side language switch.
